# Allira Bot

Telegram-бот с двумя ИИ-персонажами в крипто-тематике. **Аллира** — дерзкая
крипто-трейдерша, **Лэйн** — тихий технофилософ. Живут в личке и в группах,
ведут диалог с памятью, играют турниры на кубиках, постят новости в канал и
считают доход от аренды NFT на Marketapp.

Бот на русском языке, вся техническая документация в коде — на русском.

## Возможности

- **ИИ-чат в ЛС** — отвечает на любые сообщения, помнит последние 8 пар реплик.
  Персонажа выбирает сама по теме: крипта → Аллира, технологии → Лэйн.
- **Память диалога** — история хранится раздельно по персонажам, чтобы
  Аллира и Лэйн не путали друг друга. `/clear` очищает контекст.
- **Инлайн-режим** — `@AlliraCryptoQueen_bot <вопрос>` из любого чата.
- **Турнир на кубиках** — регистрация, 1-на-1 или все-против-все, таблица
  победителей. Состояние турнира живёт в БД и переживает рестарт сервиса.
- **Автопостинг** — новости с CoinGecko + сгенерированная картинка в канал,
  раз в 12-14 часов.
- **Отчёты Marketapp** — доход от аренды NFT: ежедневный, недельный, месячный.
  Синхронизация событий из блокчейна через TonAPI с чекпоинтом прогресса.
- **Статистика** — `/stats`, `/history`, `/leaderboard`.

## Переменные окружения

Скопируй `.env.example` в `.env` и заполни:

```bash
cp .env.example .env
```

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен от [@BotFather](https://t.me/BotFather) |
| `OPENROUTER_API_KEY` | да | Ключ [openrouter.ai](https://openrouter.ai/keys) |
| `ADMIN_CHAT_ID` | нет | Числовой Telegram ID — сюда придут алерты об ошибках |
| `NEWS_CHANNEL_ID` | нет | Канал для автопостинга. Без него автопостинг выключен |
| `MARKETAPP_API_KEY` | нет | Токен Marketapp для отчётов по аренде |
| `MARKETAPP_WALLET` | нет | TON-кошелёк, по которому считается доход |
| `TONCENTER_API_KEY` | нет | Резервный источник событий, если TonAPI недоступен |
| `TONAPI_API_KEY` | нет | Основной источник событий TonAPI |
| `DEFAULT_MODEL` | нет | Модель для Аллиры |
| `FALLBACK_MODEL` | нет | Резервная модель |
| `LANE_MODEL` | нет | Модель для Лэйна |
| `PORT` | нет | Порт ручки живости, по умолчанию `10000` |
| `LOG_LEVEL` | нет | Уровень логирования, по умолчанию `INFO` |

Узнать свой Telegram ID: напиши [@userinfobot](https://t.me/userinfobot).
Нужен именно **числовой ID** (например `123456789`). `@username` Телеграм
принимает только для публичных супергрупп, для личного чата не подойдёт — алерты
просто не придут.

Модели по умолчанию — бесплатные на OpenRouter, но у них есть лимит запросов.
Частые `429` — сигнал взять платную модель.

## Локальный запуск

```bash
git clone https://github.com/Hinorum/Allira.git
cd Allira
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # Windows: copy .env.example .env
python main.py
```

Бот поднимется в режиме polling. Ручка живости: `http://localhost:10000/health`.

**Не запускай локальную копию с тем же `BOT_TOKEN`, что на Render.** Два
процесса с одним токеном делят обновления Telegram между собой, и в логах
появляется `Conflict: terminated by other getUpdates request`.

## Деплой на Render

Репозиторий содержит `render.yaml` с готовым blueprint — при создании сервиса
Render подхватит настройки сам.

```bash
curl https://render.com/docs/static.yaml \
  -o "$(git config --get remote.origin.url | sed \
  -E 's|git@(.+):(.+)/(.+).git|\1/\2/\3|')/render.yaml"
```

### Чтобы бот не засыпал

Бесплатный инстанс Render засыпает после ~15 минут без внешнего трафика. Polling
Телеграма делает только исходящие запросы и таймер не сбрасывает, поэтому
нужен внешний пинг.

1. [UptimeRobot](https://uptimerobot.com) → **Create a new monitor**
2. Тип **HTTP(s)**, интервал **5 minutes**
3. URL: `https://<твой-сервис>.onrender.com/health`

Заодно получишь уведомление, если бот упадёт. Правильно настроенный
`healthCheckPath` в `render.yaml` этого не заменяет: Render шлёт проверки из
своей сети, и они не мешают инстансу заснуть.

## Данные

Всё хранится в SQLite-файле `allira.db` рядом с кодом.

На бесплатном Render файловая система **эфемерная**: при каждом деплое файл
пересоздаётся, статистика и история турниров обнуляются. При этом простое
контейнера в спящий режим диск **сохраняется** — турниры в процессе игры
переживают засыпание.

Если данные нужно сохранять между деплоями — нужен платный диск или внешняя
база.
